# Build Widgets live with the official A2UI packages

The owner chose live generation for every Widget. A Lesson Plan supplies a Widget brief with the teaching goal and fixed figures, including a brief for showing why each wrong Test intuition answer is wrong. ValueIt supplies the Building blocks and their tested finance calculations. The Chatbot composes them during the Lesson. The Student can change the inputs and the Chatbot can see and change them too. A Student's generated Widgets belong to their conversation and can be saved as Notes. [Lock the stack](https://github.com/SiddharthMuramkar/valueit/issues/17)

## Integration decision

Use A2UI v1.0 with the official React renderer and web core in the browser. Use the TypeScript agent package in the Next.js server with OpenAI's SDK. Keep Widget history in Neon. The package versions inspected on 28 November 2026 were `@a2ui/react@0.16.1`, `@a2ui/web_core@0.16.1` and `@a2ui/agent@0.2.1`. Pin compatible versions in the application manifest and lockfile when the app is created. That renderer declares a Zod peer dependency of `^3.25.76`. [React manifest](https://registry.npmjs.org/@a2ui/react/0.16.1) · [Web core manifest](https://registry.npmjs.org/@a2ui/web_core/0.16.1) · [Agent manifest](https://registry.npmjs.org/@a2ui/agent/0.2.1)

The official renderer supports registered calculation functions and the protocol supports updating an input after a Student changes it. ValueIt designs the appearance and behavior of its Building blocks. The app will need to validate generated output, handle a failed generation, and save and restore both the Widget and the Student's inputs. Package inspection established the available APIs. Their behavior together in a ValueIt Lesson still needs a running example. [Renderer guide](https://github.com/a2ui-project/a2ui/blob/main/typescript/renderers/react/README.md) · [A2UI data binding](https://a2ui.org/concepts/data-binding/) · [Agent integration](https://a2ui.org/guides/agent-integration/)

## Why the direct route

In CopilotKit 1.90.2 the experimental Components and surfaces engine restricts functions in live value bindings and protects inputs a Student has changed. Its separate A2UI renderer accepts a supplied catalog and exposes a v1.0 catalog's schema to the model. Whether a custom finance function and a subsequent Chatbot edit both work through that second route was never tested. The official packages expose the two operations directly and fit the chosen OpenAI SDK and ValueIt-owned history. [CopilotKit state and actions](https://docs.copilotkit.ai/generative-ui/components/state-and-actions) · [Provider implementation](https://cdn.jsdelivr.net/npm/@copilotkit/a2ui-renderer@1.90.2/dist/react-renderer/core/A2UIProvider.mjs) · [Catalog adapter](https://cdn.jsdelivr.net/npm/@copilotkit/a2ui-renderer@1.90.2/dist/react-renderer/catalog-utils.mjs)

## What remains to be demonstrated

The research included no live ValueIt Widget or owner review of its teaching quality. Each Widget requires a model call. The earlier estimate of 34–102 seconds extrapolated timings for 1,000–3,000 output tokens. The owner chose to judge the prototype on how it looks and teaches. A representative Widget should use the brief's figures, recalculate when the Student moves a control, accept the Chatbot's next change and reopen with the saved values. The owner's reaction to that Lesson will inform whether to revisit live generation.
