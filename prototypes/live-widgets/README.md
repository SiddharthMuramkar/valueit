# Throwaway prototype: live-built Widgets

This is a disposable experiment for [Do live-built Widgets look and teach well enough?](https://github.com/SiddharthMuramkar/valueit/issues/28), not the ValueIt application. It asks whether a Chatbot can compose useful, appealing Widgets live from a small catalog of Building blocks, and whether the resulting state can travel between the Student, Chatbot and database.

The three Widget briefs use invented, deliberately simple figures. They are not the completed Accounting 101 Lesson Plan. The look follows the earlier Royal blocks decision. Widget layouts are generated by the model; their allowed Building blocks and finance calculations are trusted local code.

## Run locally

```sh
npm ci
vercel link --project valueit --yes
vercel env pull .env.local --yes
npm run dev
```

Open http://127.0.0.1:3333. The server reads `OPENAI_API_KEY` (the ValueIt project's Development environment only) and `DATABASE_URL` (the ValueIt Neon development database), never shipping those values to the browser. Do not commit `.env.local` or `.vercel`. The database experiment uses a separate prototype table; the scratch file option is not a ValueIt database check. Do not deploy this prototype.

## Checks to make

- Build all three Widgets with `gpt-6.2-sol` at xhigh; record success/failure, including any validation repair. Do not use fixture output as proof of live generation.
- Compare the balance sheet against independent arithmetic: starting assets = $400 cash + $600 cart + $400 loan-funded equipment = $1,400; liabilities + equity = $400 + $1,000 = $1,400. Move the loan to $600; both totals should be $1,600. Have the Chatbot read $600 and set the loan to $800; both totals should be $1,800.
- Confirm the Student input recalculates locally, without `fetch` to the model. Save the Widget as a Note, reopen it and move the same input again; confirm the data and Building blocks remain functional. Only an actual connection to ValueIt's Neon project counts as the requested database test.
- Ask the owner to describe what each example teaches and where the look or explanation fails. Keep the decision open until the owner has judged the actual Widgets.

The initial install uses `@a2ui/react@0.16.1`, `@a2ui/web_core@0.16.1`, `@a2ui/agent@0.2.1`, and `zod@3.25.76`, as inspected during the stack decision. See `package-lock.json` for all resolved dependencies.

## Verification record (2026-11-28)

The separately labelled `/smoke` route uses handmade A2UI messages only; the real generation endpoint never returns or substitutes them. In Chrome, the official renderer displayed a balance-sheet chart, a trusted formula and a linked numeric/range control. With the input at $400, chart totals and the formula displayed $1,400; moving it to $600 caused each to display $1,600 without any model call. An additional official NodeResolver test calculated present value of $1,210 in two years at 10%, 20% and 5% as $1,000, $840.28 and $1,097.51 (rounded). The official agent parser accepted the handwritten messages. A synthetic in-place update to $800 and a scratch-file Note save/reopen through the Note route preserved the new state. No real model output or Neon data was involved in these checks.

The prototype must still be tried with the ValueIt project credentials and the owner's own review. Package compatibility on a handwritten fixture is not evidence that the model composes a good Widget. The ValueIt Vercel project was created with the owner's permission for private credential configuration; it has not been deployed.
